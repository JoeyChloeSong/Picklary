# 결과·랭킹·콘텐츠 업데이트

## 결과를 갱신하는 순서
대회 날짜가 지났다는 이유만으로 결과를 확정하지 않습니다. 공식 대회 결과나 PPA/MLP 관련 1차 기사에서 종목, 우승자, 상대, 각 게임 점수를 따로 확인합니다.

1. `data/sources.json`에 실제 확인한 URL과 확인일을 기록합니다.
2. `data/results.json`의 해당 종목 행을 수정합니다.
3. `games`는 항상 우승자 관점의 `[우승자 점수, 상대 점수]` 배열입니다.
4. 우승자만 확인했다면 점수를 추정하지 않습니다. 현재 쿠알라룸푸르 남복처럼 별도 상태로 둡니다.
5. 팀 시리즈 2–0은 `series`에, 개별 게임 점수는 `games`에 넣습니다. 서로 대체하지 않습니다.
6. `npm run check`를 실행하고 실제 페이지의 이름/방향/점수 표시를 대조합니다.

예:
```json
{
  "division": "MS",
  "winner": ["Player A"],
  "runnerUp": ["Player B"],
  "games": [[10,12],[11,9],[11,6]],
  "series": null,
  "source": "verified-source-id",
  "status": "confirmed"
}
```

예시 이름은 게시 데이터로 사용하지 않습니다. 3게임 중 앞서지 않는 쪽을 우승자로 쓰면 검사가 실패합니다.

## 현재 남겨 둔 미확인 부분
- Las Vegas 2026: 남복만 확인. 남단·여단·여복·혼복의 개별 결승은 이 판에 미입력.
- Kuala Lumpur 2026: 5종목 우승자/준우승자, 그중 4종목 게임별 점수 확인. 남복 점수 미확인.
- MLP 2026 결승: 최종 시리즈 2–0만 기록. 개별 경기별 점수를 임의로 추가하지 않음.

## 랭킹
PPA의 WPR은 종합 지표이며 종목별 세계랭킹 표와 같지 않습니다. `rankings.json`의 WPR과 independent Elo를 분리해 유지합니다. PickleWave의 화면 갱신일은 모든 원경기의 데이터 컷오프가 검증되었다는 뜻이 아닙니다. 숫자를 복사할 때 출처의 표 전체와 정렬 기준을 재확인하고, 이를 공식 DUPR 또는 PPA 종목별 순위라고 표시하지 않습니다.

## 이미지
새 제품은 사진의 대상과 정확한 모델/색상 또는 명시한 제품군을 대조합니다. 이용 근거도 `media.json` 및 권리 확인표에 추가합니다. 사진이 없으면 다른 모델로 대신 채우지 않습니다.

## 날짜의 의미
`checked`는 실제로 내용을 확인한 날짜입니다. `npm run build`를 했다는 이유로 과거 정보를 오늘 날짜로 바꾸지 않습니다. 게시 날짜는 운영자가 검토·게시할 때 갱신합니다.

## 자동화
기본 GitHub Actions는 코드·데이터 검증만 수행합니다. 경기 결과를 자동으로 생성하거나 RSS 제목만 보고 점수를 채우지 않습니다. 향후 자동 수집은 운영자가 검토할 대기 목록을 만드는 단계부터 추가하는 것이 안전합니다.
